# PS1 Link Cable

Two-player PlayStation 1 **link-cable** play between two Steam Decks over your home wifi — no
cables, no console hacking, no configuration. One Deck hosts, the other joins, and games like
**Command & Conquer: Red Alert Retaliation**, **Dune 2000**, and **Doom** play their real
two-player link modes the way they did on two PlayStations wired together in 1997.

<p align="center"><em>Host a game · Join a game — pick from a controller-driven menu,
hosts are discovered on the LAN automatically.</em></p>

## How it works

The PS1 "link cable" was a serial cable between two consoles, each running its own copy of the
game. Emulating that faithfully over a real network fails — the protocol needs hundreds of
ordered round trips per payload, so even one millisecond of wifi latency stalls it hopelessly.

PS1 Link Cable sidesteps the problem: **both emulated consoles run on the hosting Deck**, linked
over loopback where the round trip fits inside a frame. The second player's console is then
*streamed* to their Deck — video encoded per-frame, raw PCM audio, controller input flowing back
— all over plain TCP with no container and no clock to negotiate, tuned end-to-end for latency:

```
 HOST DECK                                          JOINING DECK
┌───────────────────────────────┐                  ┌──────────────────┐
│ console A (your screen)       │                  │                  │
│    ⇅ SIO1 link over loopback  │   h264 video ►   │  bespoke player  │
│ console B (headless)──export──┼── raw PCM audio ►│  (~2 frames      │
│                     stream-host│  ◄ pad input    │   behind, no     │
└───────────────────────────────┘                  │   backlog ever)  │
        ▲ announces itself on the LAN (UDP)        └──────────────────┘
```

Both Decks run the **same app**: a Steam-library entry with a controller menu. Hosting lists your
games; joining lists hosts heard on the network. When a session ends, the menu returns.

The emulator is a patched [PCSX-Redux](https://github.com/grumpycoders/pcsx-redux): a
frame/audio export socket, a link-transport acknowledgement scheme that keeps the streamed
console at full speed, and a couple of upstream-worthy fixes found along the way (a 24bpp
screenshot bug that broke every FMV capture, and the SIO DSR interrupt, which the hardware has
and the emulation lacked).

## What you need

- **Two Steam Decks** on the same network. (One Deck alone gives you couch play — both players
  on one screen. A Linux PC can stand in for either side with some assembly; Windows is not
  supported yet.)

**Only the hosting Deck needs game files.** Both consoles run on the host, so a joining Deck
needs nothing but this app — no emulator, no BIOS, no games. Install on both, and whoever owns
the games hosts.

The hosting Deck needs:

- **Your own PS1 BIOS** (`scph7001.bin` or compatible). Not included, not downloadable from
  here — dump it from your own console.
- **Your own game discs**, dumped as `.bin/.cue`. Not included either. **Complete dumps
  matter**: a rip missing its CD-audio tracks fails in strange ways (Doom boot-loops at
  LOADING if its seven audio tracks are absent — silent stub tracks in the cue are the
  workaround, and this repo's tooling handles that).
- Games must actually support the link cable, and their protocol must survive emulation.
  Validated so far: **Retaliation**, **Dune 2000**, **Doom**. The menu greys out anything
  known broken.

## Installing

> **Status: working, and installation is the rough edge.** Today the installers run from a
> Linux PC over SSH to each Deck; a double-click on-Deck installer is the next milestone.

From a Linux machine with SSH access to your Decks:

```sh
# hosting Deck (emulator + games + menu + streamer)
./deploy/deck/gamemode/install.sh <hosting-deck-hostname>

# joining Deck (player + menu; no emulator, BIOS, or games needed)
./deploy/deck/stream/install-joiner.sh <joining-deck-hostname> <hosting-deck-ip>
```

Both register **"PS1 Link Cable"** in the Steam library. BIOS goes in
`~/ps1-lan-link/bios/`, game cues in `~/ps1-lan-link/roms/` on the hosting Deck; the menu
lists whatever it finds (`games.conf` gives known discs friendly names).

Steam grid artwork is generated by `deploy/deck/art/generate-art.py` — copy its output into
`userdata/<uid>/config/grid/` named for your shortcut's appid.

## Network & security notes

- The **hosting Deck** listens on the LAN: video/audio/pad streaming (TCP 6690–6692) and a
  1-per-second discovery beacon (UDP 6693). These carry media and button states only.
- The emulator's own control surface (an unauthenticated debug HTTP API) binds **loopback
  only** and is never reachable from the network.
- Nothing needs `sudo` — not to install, not to play.

## Repository tour

| Path | What |
|---|---|
| `deploy/deck/` | Everything that ships to a Deck: menu, launcher, streaming, installers, art |
| `pcsx-redux/` | The patched emulator (fork of upstream, MIT) |
| `tools/`, `repro/` | The measurement instruments and reproduction rigs the fixes came from |
| `HANDOVER.md` | The full engineering log — every finding, dead end, and withdrawn diagnosis |
| `docs/FINDINGS.md` | The evidence trail behind the design |

The development history is unusually honest reading: five wrong FMV diagnoses before the real
one, a "link-broken" game that turned out to be a truncated rip, and an input-lag hunt that
ended one buffered read away from where it started. If you enjoy debugging war stories, start
with `HANDOVER.md`.
